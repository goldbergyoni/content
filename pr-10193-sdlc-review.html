My review

Approve once the duplication is resolved

High value, near-zero runtime risk — and the invariants are grounded in real code (I verified the cited symbols all exist), which makes them checkable rather than aspirational. But this is not a clean "ship it": the same rules are written out across all three docs, and the language leans on forced emphasis. Both cut against the very SDLC standards a skill PR should model. Fix the duplication and tone, then merge.
What's strong
  • Right shape for a skill. SKILL.md is lean and routes outward; read-only allowed-tools is honest for a domain guide.
  • Invariants tied to code. Every rule names the file that enforces it — canChangeStakeholderVisibility.ts, buildSecurityStakeholderItems, useDeleteManyDocuments, AISuggestionsModal → resolveActiveStep, selectAll: 'currentPage'. I checked: they all resolve.
  • The test matrix is the headline value. A change-type → test-file map across a 24-file suite removes the single most expensive question an agent faces here.
  • Security framing is correct. Visibility/bulk flagged as high-blast-radius, and the frontend is correctly described as not the enforcement layer.
What must change before merge
  1. Kill the three-way duplication (blocking). ~12 rules are restated across SKILL.md, AGENTS.md, and INVARIANTS.md — several near-verbatim (e.g. "Never check user.role === 'admin'" appears word-for-word in two files; module-gating and "AI advisory until save" appear in all three). One home per fact: SKILL.md routes only, AGENTS.md explains concepts, INVARIANTS.md holds the enforceable rules. See the Guidelines tab for the full list.
  2. Tone down forced language. "must not regress", "non-negotiable", a bold lead-in on all 12 invariants, "high-risk", repeated "Never/Always/Do not". When everything shouts, nothing does.
  3. Add a commands section to AGENTS.md (CodeRabbit's major). The run command lives only in the playbook; the leaf AGENTS.md should carry it inline.
  4. Trim AGENTS.md. ~218 lines loaded every Documents Room turn; the generic example lists (visibility/bulk/action categories) can drop ~25%.
  5. Fill the PR description. What/How are blank — a docs-about-good-context PR should model it.
Open question

Does INVARIANTS.md need to be a separate file? It's a non-standard name (loads only when pointed to) and it overlaps heavily with AGENTS.md. Folding it in as an "Invariants" section would remove most of the duplication in one move.
